## 追加任务：实现纯 `/admin` 命令（用户要求去掉命名空间前缀）

### 调研结论（网易开发者文档）
| 方案 | 能否纯 /admin | 说明 |
|------|:---:|------|
| Mojang Script API `customCommandRegistry` | ❌ | 强制 `namespace:name` 格式；且需基岩版 1.21.80+ / SAPI 2.0 |
| **网易 `netease_commands` 自定义指令** | ✅ | JSON 配置，name 字段支持纯名字（如 /explode、/customtest2） |
| `chatSend` 拦截 `/admin` | ❌ | `/` 开头走命令系统，聊天事件收不到 |

### 实施内容（网易 ModAPI / Python 2 + netease_commands）
新增 4 个文件到 behavior_pack：
1. `netease_commands/cuffed_admin.json` — 指令定义（name: "admin"，permission_level: game_directors，args: target 类型）
2. `cuffed_scripts/__init__.py` — Python 模块标记（必须存在）
3. `cuffed_scripts/modMain.py` — Mod 入口（@Mod.Binding + InitServer 注册 System）
4. `cuffed_scripts/CuffedAdminServerSystem.py` — 监听 `CustomCommandTriggerServerEvent`，用 `CreateTag(entityId).AddEntityTag("cuffed:admin")` 加标签

### 关键 API（网易 ModAPI）
- 事件：`CustomCommandTriggerServerEvent`，参数 `command` / `args`(list of dict) / `variant` / `origin` / `return_msg_key`
- target 类型参数：`args[0]['value']` = entityId 元组
- 加标签：`serverApi.GetEngineCompFactory().CreateTag(entityId).AddEntityTag("tag")`
- 系统注册：`serverApi.RegisterSystem(ModName, SystemName, "脚本目录.类名.类名")`

- ⚠️ JS(Script API) + Python(ModAPI) 共存于同一行为包 → 网易版是否支持**未验证**，需测试

## 追加：方块格式修复（第二次报错）

### 新错误
```
blocks/reinforced_stone.json | minecraft:cuffed:blocks | Invalid identifier
blocks/reinforced_stone.json | Unexpected version for the loaded data
```

### 根因（网易自定义方块文档）
1. **方块 format_version 必须用 1.10.0 或 1.16.0**（网易推荐 1.10.0）
   - 1.16.100+ / 1.21.x 属于"新版方块"，**需要开启实验性玩法**，网易不推荐
2. **方块的 group 机制与物品不同**：引擎会给 group 拼 `minecraft:` 前缀，写 `cuffed:blocks` 会变成 `minecraft:cuffed:blocks`（双重冒号 = Invalid identifier）
   - 方块只能用原版分组（如 `itemGroup.name.stone`）或不设 group

### 修复内容
- 两个方块改用 **1.10.0 旧版格式**（无需实验性玩法，发布后人人可用）
- 旧版字段对照：
  | 新版（1.21.x） | 旧版（1.10.0） |
  |---|---|
  | `destructible_by_mining.seconds_to_destroy` | `minecraft:destroy_time` |
  | `destructible_by_explosion.explosion_resistance` | `minecraft:explosion_resistance` |
  | `map_color: [r,g,b]` | `map_color: "#RRGGBB"` |
  | `geometry` + `material_instances` | 不需要（默认立方体） |
  | `loot: {table: "..."}` | `loot: "路径字符串"` |
  | `menu_category` | `category` + `register_to_creative_menu` |
- 显示名改用语言文件 `tile.cuffed:xxx.name`（旧版没有 display_name 组件）
- **新增 `resource_pack/blocks.json`**：旧版方块的贴图在资源包根目录定义（不是 behavior 侧）

### 副作用（需告知用户）
- ❌ 失去"镐子加速"（`item_specific_speeds` 是新版特性），挖掘时间是固定的 6000 秒
- ❌ 方块无法用 `menu_category.group` 自定义分组（旧版不支持）；网易另有 `netease_tab` 机制可试

### 待验证
用户需重启测试：方块是否加载、物品是否正常、`/admin` 与 `!admin` 是否可用

## 第三轮修复：快拆失效 + 牢门改造

### 用户反馈 4 点
1. 有 `cuffed:admin` 标签但挖不动加固方块
2. 牢门贴图"什么鬼"（门的 top 贴图当立方体渲染）
3. 问挂锁/密码锁怎么用在牢门上
4. 牢门应该像木门一样是"门"的形状，不该是方块

### 修复 1：快拆失效根因
- **旧逻辑死循环**：方块硬度 6000 秒 → 玩家永远挖不完 → `playerBreakBlock` 事件永不触发 → 快拆代码根本没机会执行
- **新方案**：方块硬度降到 0.2 秒 + `beforeEvents.playerBreakBlock` 拦截
  - 非管理员 → `event.cancel = true`（挖不动）
  - 管理员 → 放行（0.2 秒即破）
- 新增 `isAdminPlayer()` 统一判断（创造模式 / cuffed:admin tag / isOp）

### 修复 2-4：牢门改造（方块 → 放置原生铁门）
- **删除** `behavior_pack/blocks/cell_door.json`
- **新增** `behavior_pack/items/cell_door.json`（物品，用原模组 `textures/item/cell_door.png`）
- **新增** `behavior_pack/recipes/cell_door.json`（6 铁锭 = 1 牢门）
- **资源包**：`blocks.json` 移除 cell_door；`item_texture.json` 加 cell_door
- **main.js 新增**：
  - `placeCellDoor()` — 右键方块上方放原版铁门（两格高，按玩家朝向）
  - `toggleDoor()` — 铁门手开（原版铁门只能红石开，用脚本改 open_bit 实现手开）
  - `getLockHost()` — 锁数据统一存在铁门下半部分（箱子=自身）
  - `getDoorHalves()` — 获取门上下两半
- **锁系统**：`isLockableBlock()` 改为 箱子 + `minecraft:iron_door`

### 待测试验证点（重要）
- ⚠️ 铁门方块状态名是否正确：`minecraft:cardinal_direction` / `minecraft:vertical_half` / `open_bit`
  - 若不正确，`BlockPermutation.resolve` 会抛异常（已 catch，会提示"放置失败"）
- ⚠️ 原版铁门右键是否触发 `playerInteractWithBlock` 事件（手开依赖此事件）
- 铁门目前是原版硬度（可用镐挖），未纳入加固保护

### 教训
- 高硬度方块 + 破坏事件做权限控制是**死路**（事件不触发）
- 正确姿势：低硬度 + before 事件 cancel 拦截
